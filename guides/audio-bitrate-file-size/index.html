Audio bitrate and file size,
without the guesswork.

For a fixed duration, a lower encoded bitrate usually means a smaller file. The useful choice is the smallest sharing copy that still sounds clear in its destination.

Estimate the sizeChoose a starting pointExport and check

01. Start with duration and bitrate.

Bitrate measures encoded data per second. At a constant bitrate, doubling the duration or the bitrate roughly doubles the audio payload. The filename extension alone does not tell you the bitrate.

Estimated MB = kbps × seconds ÷ 8,000

Here MB means 1,000,000 bytes. A file manager using MiB may show a different number.

For a 30-minute recording at 96 kbps: 96 × 1,800 ÷ 8,000 = 21.6 MB before overhead. This is a transparent estimate, not a promise that an encoder will hit an exact limit.

02. Choose a starting point, then listen.

A bitrate is not a universal quality score. The codec, source recording and content all matter. A noisy lecture and a stereo music mix do not need the same test.

1

One voice, for listening

For a mono MP3 test, try 64 or 96 kbps. Check quiet words and consonants before using a full recording. These are starting points, not guaranteed quality levels.

2

Stereo matters

Keep stereo for music, ambience or separate speakers on different channels. A 128 or 192 kbps MP3 test can show whether the sharing copy is clear enough for your purpose.

3

You will edit it again

Retain the original or a lossless working copy. Make a smaller lossy version for sharing after editing. Repeated lossy exports can discard more detail.

Starting points and re-encoding caveat: Audacity’s MP3 export documentation. Its recommendations concern MP3 exports, not every audio codec.

Mono does not always halve a compressed file.

At the same total constant bitrate and duration, mono and stereo have about the same payload. Mono gives an encoder fewer channels to represent. It saves space when that lets you use a lower bitrate.

Constant and variable bitrate are different estimates.

CBR

Constant bitrate

The data rate stays roughly fixed, so duration gives you a useful size estimate. Choose it when a receiving workflow explicitly requires it.

VBR

Variable bitrate

The encoder spends different amounts of data on different passages. A quality setting is not an exact size promise. Check the exported file’s actual size.

See Apple’s explanation of import bitrate and VBR and the mode descriptions in the Audacity source above.

03. Make one copy and verify it.

  1. Keep a source copy.

    Start from the best original you have. Raising the bitrate of an already lossy file does not recover detail that was discarded.

  2. Test a representative section.

    Include soft speech, background noise or busy music. Export once, listen at normal volume and compare with the source. If speech sounds watery or dull, try a less aggressive setting.

  3. Check the actual file.

    Inspect duration, size and playback in the destination. Leave room under any hard upload limit. If it is still too large, lower the bitrate or trim genuinely unnecessary material and test again.

If the result is not what you expected

  • WAV stays large: uncompressed PCM size depends on sample rate, bit depth and channels. A compressed-audio bitrate estimate is not the right setting model.
  • Changing the extension did nothing: renaming a file does not re-encode its audio.
  • VBR misses a size target: use the actual exported size, or a suitable constant/average-rate mode when your encoder offers one.
  • The destination refuses a small file: check accepted formats and duration separately. Size alone does not establish compatibility.
